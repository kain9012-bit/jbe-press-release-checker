# 보도자료 공공언어 자가검증

보도자료 초안을 넣으면 **국립국어원 공문서등 평가 기준**에 따라 고칠 곳을 짚고,
반영한 수정본과 점검표를 만들어 주는 웹 도구입니다.

넣는 곳은 상자 하나입니다. 글을 그대로 붙여 넣어도 되고, 쓰던 한글 파일(.hwp, .hwpx)을
그 상자에 끌어다 놓아도 됩니다. 파일을 놓으면 제목·본문이 상자에 들어가고 배포일·부제·부서·
담당자는 화면 뒤에서 그대로 들고 있다가 hwpx 머리말에 되돌려 놓습니다.
결과는 **전북교육청 보도자료 양식이 적용된 hwpx 파일**로 나옵니다.

상자의 **첫 줄이 제목, 나머지 줄이 본문 문단**입니다.

## 화면은 되도록 비운다

첫 화면에 있는 것은 **상자 하나와 단추 넷**뿐이다. 머리말 표(배포일·부서·담당자)는 파일에서
자동으로 채워지므로 첫 화면에 늘어놓지 않고, 내려받기 직전에 여는 접힌 칸
(‘hwpx 머리말 정보’) 한 곳에만 둔다. 같은 것을 두 곳에 두지 않는다는 뜻이다.

검토를 누르면 입력 띠는 한 줄(‘초안 284어절 · 1,226자 / 초안 고치기 / 처음부터’)로 접히고
결과가 그 아래로 이어 붙는다. 초안을 다시 만지고 싶으면 ‘초안 고치기’로 편다.

내놓는 파일은 hwpx 하나다. txt 내려받기는 두지 않는다(글자만 필요하면 ‘복사’를 쓴다).

작성 부서가 스스로 검증하고, 대변인실의 반복 검토·수정 부담을 줄이는 것이 목적입니다.

## 화면 규격

내가 만드는 웹 화면은 한 벌처럼 보여야 하므로 [jbe-weekly-policy-meeting](https://github.com/kain9012-bit/jbe-weekly-policy-meeting)
과 같은 규격을 쓴다. 새 화면을 붙일 때도 여기서 벗어나지 않는다.

- `src/index.css` — KRDS 토큰을 Tailwind 기본 팔레트에 덮어씌운 것. k-edu-policy 것을 그대로 가져왔다.
- `src/components/Ui.tsx` — `Badge` `SectionTitle` `EmptyState` `Stat` `Notice`,
  그리고 버튼 두 벌(`BTN_PRIMARY` 진회색 / `BTN_GHOST` 테두리)과 `CARD`.
- `src/components/Header.tsx` — 회색 안내 띠(비공식 고지) + 파란 사각 로고 + 서비스명·기관명 + 탭(`border-b-[3px]`).
- 본문은 `max-w-7xl mx-auto px-4 sm:px-6 lg:px-8`, 첫 화면은 화면 폭을 채우는 `bg-blue-50` 띠.
- 푸터는 `bg-slate-900` 두 칸(왼쪽 서비스 설명 / 오른쪽 출처), 오른쪽 아래 '맨 위로' 버튼.

## 무엇을 보나

| 평가 항목 | 지표 | 이 도구가 하는 일 |
|---|---|---|
| 용이성 | 외국 글자(로마자·한자) 사용 | 한글 병기 없이 쓴 로마자·한자를 모두 찾아냅니다 |
| 용이성 | 우리말로 대체 가능한 외래어 | 평가용 용어 목록 1,540개 + 필수 개선 행정용어 100개 + 일본어 투 50개로 대조 |
| 정확성 | 표기의 정확성 | 두음 법칙, 외래어 표기법, 띄어쓰기, 괄호 뒤 조사, 문장 부호 |
| 정확성 | 표현의 정확성 | 번역 투, 이중 피동, 사물 존대, 어휘 오용 |
| 소통성 | 공공성 | 권위적 표현, 차별적 표현 |
| 소통성 | 이해가능성 | 지나치게 긴 문장 |

문맥을 봐야 판단할 수 있는 것(주술 호응, 접속의 대등성, 생략, 중복)은 규칙으로 잡지 않고
**AI 문맥 검토**에 맡깁니다. 첫 화면에서 **‘규칙으로 검토’와 ‘AI까지 검토’ 중 하나를 고릅니다.**
AI를 쓰지 않아도 규칙 검사는 그대로 돌아가고, 규칙으로 먼저 본 뒤 결과 화면에서 AI를 덧붙일
수도 있습니다.

모형 이름은 코드에 박아 두지 않습니다. 회사 사정으로 수시로 없어지기 때문입니다
(실제로 `gemini-2.5-flash` 가 신규 사용자에게 막혔습니다). 설정 창의 **‘쓸 수 있는 모형
불러오기’** 를 누르면 넣어 둔 키로 그 회사에 물어 목록을 받아 오고, **새 판이 위로** 오게
정렬합니다(그림·음성·임베딩 모형은 뺍니다).

다만 **목록에 있다고 내 키로 다 되는 것은 아닙니다.** 구글은 신규 사용자에게 막은 옛 모형도
목록에는 그대로 내려 줍니다. 그래서 **‘이 모형으로 시험 호출’** 을 같이 뒀습니다. 한 마디만
물어보고 되는지 알려 줍니다.

설정은 `prc.ai.config.v2` 로 저장합니다. v1 에는 모형 이름까지 저장했는데, 그 모형이 없어지면
브라우저에 죽은 이름이 남아 계속 404 가 났습니다. v2 로 넘어올 때 **키만 물려받고 모형 이름은
버립니다.**

## 점검표는 못 하는 것을 못 한다고 적는다

공공언어의 요건 15항목 중 **규칙이 실제로 보는 것은 10항목**입니다. 나머지 5항목(단락 구성,
정보의 형식·양·배열, 시각적 편의)은 사전 대조로 잡히는 것이 아니라 **아무 규칙도 보지 않습니다.**

예전에는 이 5항목에도 ○ 가 붙었습니다. 아래에 ‘지켰다는 보증이 아닙니다’ 라고 적어 두었지만,
사람은 동그라미를 보면 통과로 읽습니다. 실제 보도자료 하나를 넣으면 ○ 가 11개 떴는데 그중
5개는 **아무도 안 봤다는 뜻**이었습니다. 자가검증 도구가 잘못 ‘괜찮다’ 고 말하는 것은 아무 말도
안 하느니만 못합니다.

그래서 ○ 를 없애고 표를 둘로 갈랐습니다.

- **규칙이 본 것** — `걸림 없음` 또는 `n건`. ‘걸림 없음’ 은 규칙에 안 걸렸다는 뜻일 뿐이라고
  아래에 적어 둡니다.
- **규칙이 못 보는 것** — 체크 표시를 아예 주지 않고, 대신 **눈으로 무엇을 볼지** 한 줄씩
  적어 둡니다(“가장 중요한 것이 첫 문단에 왔는지 보세요. 보도자료는 두괄식입니다.”).

일부만 보는 항목은 못 보는 쪽을 밝힙니다. ‘문장을 문법에 맞게’ 는 번역 투·피동·높임·괄호 뒤
조사까지만 보고 **주술 호응과 비문은 AI 검토를 켜야** 봅니다.

어느 항목을 규칙이 보는지는 **손으로 적지 않습니다.** `EMITTABLE_SUBS` 에 규칙이 실제로 낼 수
있는 지표를 모아 두고 `isRuleChecked()` 가 런타임 대조와 같은 방식으로 따집니다. 손으로 표를
만들어 두면 규칙을 고쳤을 때 표가 조용히 거짓말을 합니다. 실제로 ‘단락’·‘정보성’·‘정보량’·‘배열’
은 그 지표를 내는 규칙이 하나도 없는데 점검표에서는 계속 ○ 를 받고 있었습니다.

복사해 가는 글도 화면과 같은 말을 합니다.

## 원문과 지적을 잇는 법

원문에서 칠한 곳을 누르면 오른쪽 목록이 그 카드까지 굴러가고, 카드를 누르면 원문의 그 자리로
간다. 누른 쪽은 건드리지 않는다 — 원문을 눌렀는데 원문이 움직이면 읽던 자리를 잃는다.

**고른 자리는 색을 뒤집는다**(검정 바탕 흰 글씨). 옅은 색 위의 가느다란 테는 칠한 자리가 열댓
개씩 있는 글에서 눈에 안 띈다. 축 색깔(파랑·빨강·노랑)과 겹치지 않는 검정을 쓰고, 오른쪽
카드도 같은 검정으로 테를 둘러 **같은 색이면 같은 것**으로 읽히게 한다.

## 카드에 적힌 말이 곧 들어가는 말이다

`replacementFor()` 에 원문을 같이 넘겨야 조사 받침이 맞춰진다(`agreeJosa`). 카드를 그릴 때
이걸 빠뜨려서, **카드에는 ‘로’ 라고 적히는데 수정본에는 ‘으로’ 가 들어갔다.** 결과가 더 옳긴
했지만 약속한 말과 실제가 다른 것은 그 자체로 고장이다. 이제 두 곳이 같은 값을 쓴다.

## 중계가 붙으면 고를 것이 하나도 없다

`VITE_PROXY_URL` 이 있으면 담당자가 정할 것이 없다. 어느 회사에 물을지도, 어느 모형을
쓸지도 서버가 정한다. 그래서 화면에서 **고르는 자리를 통째로 없앤다.**

| | 중계 있음 | 중계 없음 |
|---|---|---|
| 설정 톱니바퀴 | **없다** | 있다 (키를 넣어야 하니까) |
| 검토 단추 | **`검토하기` 하나** | `AI까지 검토` / `규칙으로만 검토` 둘 |
| 두 방식 설명 | 없다 | 있다 |

담당자가 하는 일은 셋이다. **파일 끌어다 놓기 → `검토하기` → `한글 파일 내려받기`.**

앤트로픽이니 제미나이니 3.6 플래시니 하는 것은 배포하는 사람이 한 번 정하고 끝이다.
쓰는 사람은 그런 것이 있는 줄도 모르는 것이 맞다.

## 화면에는 고친 글과 내려받기만 둔다

담당자는 넣고 받으면 끝이어야 한다. 결과 화면에 보이는 것은 **고쳐진 글**과
**‘한글 파일 내려받기’** 하나다.

나머지는 접어 둔다. 지우지 않는다 — 볼 사람은 펴서 본다.

- `＋ 무엇을 고쳤는지 보기` — 단계 표시, 원문·지적 목록, 모두 고치기·되돌리기·복사 단추
- `＋ 점검표` — 공공언어의 요건 15항목

만드는 쪽 사정(단계가 셋이라는 것, 세 번 물어 표를 센다는 것, 규약을 몇 번 어겼다는 것)은
**전부 화면 밖에 둔다.** 그게 결과에 영향을 주긴 하지만, 담당자가 알아야 쓸 수 있는 것이면
설계가 잘못된 것이다.

이 정리로 결과 화면 길이가 3,670px 에서 1,301px 로 줄었다.

## 세 단계

‘AI까지 검토’ 는 안에서 세 단계를 돈다. 사람은 한 번 누른다. 결과 화면 맨 위에 **어느
단계가 무엇을 했는지** 그대로 보여 준다.

```
1차 규칙 검토   16건   용어 목록·표기 규범 대조
2차 AI 검토      1건   조사·호응·비문·군더더기
3차 재검토   1건 되돌림  고친 자리를 다시 확인
```

‘규칙으로만 검토’ 를 누르면 2·3차 칸이 점선으로 남고 ‘안 돌림’ 이라고 적힌다. 지적 수 하나만
보여 주면 반쪽 검사와 끝까지 돌린 것이 같아 보인다.

## 한 번 누르면 세 번 돈다

‘AI까지 검토’ 는 안에서 세 단계를 돈다. 사람은 한 번 누른다.

1. **문맥 검토** — 규칙이 못 보는 호응·비문·군더더기를 찾는다.
2. **빈자리 채우기** — 규칙이 넣을 말을 정하지 못한 자리를 문장째 주고 받아 온다.
3. **검수** — 앞의 둘이 고쳐 놓은 자리를 **다시 물어 잘못된 것을 골라낸다.**

셋째가 핵심이다. 새로 찾는 것이 아니라 **고친 자리만 옳으냐고 묻기 때문에** 답을 그 자리에
그대로 되돌릴 수 있다. 걸린 자리는 지우지 않고 꺼 두고, 카드에 왜 걸렸는지 적는다. 판단은
사람이 한다.

검수는 **켜진 것만 보지 않는다.** AI 제안은 기본이 꺼짐이라, 켜기 전에 미리 걸러 두어야
‘모두 고치기’ 를 눌렀을 때 나쁜 것이 딸려 들어가지 않는다.

## 단계마다 제 하네스를 둔다

`src/lib/stages.ts` 에 세 단계의 **받는 것 · 하는 일 · 하지 말아야 할 일 · 내는 것**을 적고,
그것을 지켰는지 보는 함수(`guard1` `guard2` `guard3`)를 바로 옆에 둔다. 전에는 확인이
흩어져 있었다 — 2차에는 규약이 있고 3차에는 id 거르기가 있고 **1차에는 아무것도 없었다.**

| | 1차 규칙 검토 | 2차 AI 검토 | 3차 재검토 |
|---|---|---|---|
| 받는 것 | 원문 | 원문 + 1차가 잡은 것 | 고쳐 놓은 자리 목록 |
| 하는 일 | 사전·규범 대조 | 절차 여덟 단계 훑기 | 각 고침이 옳은지 판정 |
| 안 하는 일 | 문맥 판단 | 1차가 잡은 자리 다시 짚기 | 새로 찾기 |
| 하네스가 막는 것 | 자리가 원문과 어긋남, 축이 셋 중에 없음, 숫자·병기를 건드리는 고침 | 지표 이름이 목록에 없음, 지어낸 조각, 숫자 바뀜, 병기 뗌, 자리표시, **1차와 중복** | 묻지 않은 id 를 답함 |

1차에 걸리는 것은 모형이 아니라 **우리 사전·규칙의 버그다.** 규칙은 손으로 늘리는 것이라
잘못 고치면 자리가 밀리거나 숫자를 건드리는 고침이 나올 수 있다.

## 왜 답이 달라지나

AI 는 문맥 판단을 못 하지 않는다. 오히려 그게 규칙이 못 하는 일이다. 답이 달라지는 데는
다른 이유가 셋 있다.

**첫째, ‘고칠 곳을 찾아라’ 는 정답이 하나인 질문이 아니다.** 같은 보도자료를 국어 전문가
셋에게 주면 `등를` 이 틀렸다는 데는 셋 다 동의한다. 그런데 `산업 체험하며` 를 `산업을
체험하며` 로 고칠지, `시간을 갖게 되었다` 를 손볼지는 사람마다 갈린다. **모형이 흔들리는
자리는 사람도 갈리는 자리다.** 명백한 오류에서 흔들리는 것이 아니다.

**둘째, 온도 0 도 완전한 결정성이 아니다.** 회사 쪽에서 여러 요청을 묶어 처리하는데, 묶이는
방식에 따라 부동소수점 셈의 차례가 달라진다. API 로는 어쩔 수 없는 부분이다.

**셋째, 넣는 글이 달라지면 답도 달라진다.** 수정본을 다시 넣으면 다른 글이다. 그때 새 지적이
나오는 것은 흔들린 것이 아니라 맞는 동작이다.

첫째가 대부분이고, 그래서 **표 세기가 먹힌다.** 명백한 오류는 세 번 다 나오고, 갈리는 자리는
한두 번만 나온다. 흔들림 자체가 ‘이건 확실하고 저건 갈린다’ 는 정보다.

**표는 화면에 안 보인다.** 몇 번 물어 몇 번 나왔는지는 만든 쪽 사정이지 담당자가 알 일이
아니다. 표가 하는 일은 **체크상자의 기본값을 정하는 것** 하나다.

- 세 번 다 짚은 것 → **켜 둔다.** 그대로 수정본에 들어간다
- 두 번만 짚은 것 → **꺼 둔다.** 사람이 보고 켜면 된다
- 한 번만 짚은 것 → 아예 안 보여 준다

읽을 것을 늘리지 않는다. 화면에는 체크상자가 켜져 있느냐 꺼져 있느냐만 보인다.

## 답이 들쑥날쑥한 것을 표로 누른다

온도를 0 으로 못 박아도 답이 완전히 같지는 않다. 그래서 **2차는 같은 글을 세 번 물어,
두 번 이상 나온 것만 채택한다.** 한 번만 나온 지적은 대개 헛것이다.

세 번을 한꺼번에 물으므로 기다리는 시간은 거의 그대로다. 값은 검토 한 번에 20~50원에서
30~80원쯤 된다.

`bench/voting.test.mjs` 가 이걸 보여 준다. 회차마다 다르게 답하는 가짜 모형을 물리면

```
1회만 물으면: 3가지 결과
   1번째: 개최했다,운영한다,을 통해
   2번째: 개최했다,마련 했다,을 통해
   3번째: 배웠다,상담을,을 통해
3회 표 세기: 1가지 결과로 고정
```

카드에도 **‘3회 중 2회 지목’** 이라고 적어 둔다. 표가 몇인지 보고 사람이 판단한다.

제미나이에는 `responseSchema` 로 답의 모양까지 못 박는다. 지표 이름은 여덟 개 중에서만
고를 수 있어서, 틀린 이름은 나온 뒤에 거르는 것이 아니라 **애초에 나오지 못한다.**

## AI 를 붙잡아 두는 하네스

지시문에 부탁만 해 두면 모형은 부를 때마다 다르게 답한다. 부탁은 부탁대로 하되
**어겼는지는 코드가 본다.** `src/lib/procedure.ts` 가 그 자리다.

### 절차를 순서로 못 박는다

여덟 단계를 번호를 매겨 준다. 좁고 확실한 것부터 넓고 판단이 필요한 것 순이다.

`조사·어미` → `주술 호응` → `접속·수식` → `시제` → `군더더기` → `문장 길이` →
`외국어 표현` → `권위·차별`

단계마다 **보는 것**과 **보지 않는 것**을 같이 적는다. ‘보지 않는 것’ 이 있어야 앞 단계나
규칙 검사가 이미 한 일을 뒤에서 또 꺼내지 않는다.

AI 가 내는 지표 이름은 **이 여덟 개 중 하나여야 한다.** 그 밖의 이름이 오면 버린다. 축
(용이성·정확성·소통성)은 모형에게 묻지 않고 절차가 정해 둔 것을 쓴다. 물어볼 것을 줄이면
틀릴 자리도 줄어든다.

### 규약은 코드가 확인한다

| 어긴 것 | 어떻게 아나 |
|---|---|
| 숫자가 바뀜 | 고치기 전과 후의 숫자를 모아 견준다. 하나라도 다르면 버린다 |
| 병기를 떼어 냄 | `한글(로마자)` 꼴의 개수가 줄면 버린다. 다는 것은 괜찮다 |
| 자리표시가 섞임 | `~`, `(으)로` 가 들어 있으면 버린다 |
| 원문에 없는 조각을 지어냄 | 원문에서 글자 그대로 찾지 못하면 버린다 |
| 지표 이름이 목록에 없음 | 절차의 여덟 이름이 아니면 버린다 |
| 고친 말이 비었음 | 빈 답을 버린다 |

버린 것은 세어서 `violations` 로 돌려준다. **그 숫자가 지시문이 먹히고 있는지 알려 준다.**

세 단계에 다 건다. 채우기는 넣을 말이 규약을 지키는지 보고, 검수는 **묻지 않은 id 를 답하면
받지 않는다**(검수는 판정만 하는 단계다).

`bench/violations.test.mjs` 가 이걸 확인한다. 일부러 규약을 어기는 가짜 모형을 물려 여섯 개를
내게 하면 다섯이 걸리고 멀쩡한 하나만 남는다.

### AI 가 점검표의 빈칸을 채운다

절차의 여덟 지표를 점검표 항목에 이어 두었다. 규칙이 못 보던 칸(문법·정보량·문장 길이)이
**AI 를 켜면 채워진다.** 규칙만 돌리면 그대로 ‘규칙이 못 보는 것’ 에 남는다.

## 어디에 올리나 — 중계는 하나만 쓴다

키는 웹페이지에 둘 수 없다. 브라우저가 읽을 수 있으면 사람도 읽는다. 그래서 키를 들고 대신
요청해 주는 것이 하나 있어야 하는데, **올리는 곳에 따라 둘 중 하나만 쓰면 된다.**

| | 버셀 (`api/`) | 깃허브 페이지스 + 클라우드플레어 (`proxy/`) |
|---|---|---|
| 어디에 도나 | 웹페이지와 **같은 주소** | 따로 뜬 Worker |
| CORS | 없다 | 허용 주소 목록을 맞춰야 한다 |
| 주소가 바뀌면 | 할 일 없다 | `ALLOWED_ORIGINS` 를 고쳐야 한다 |
| 분당 제한 | 없다 | 있다 (분당 30회) |
| 넣을 것 | `GEMINI_API_KEY`, `VITE_PROXY_URL=/api/gemini` | `wrangler secret`, 저장소 변수 `PROXY_URL` |

**버셀에 올릴 거면 `api/` 쪽이 간단하다.** 같은 주소라 CORS 를 아예 안 만난다.
자세한 것은 `api/README.md` 와 `proxy/README.md`.

어느 쪽이든 **구글 클라우드 콘솔의 결제 상한이 마지막 안전장치다.** 문을 좁혀 두긴 했지만
브라우저가 붙이는 표시는 브라우저 밖에서 꾸며 낼 수 있다.

## 하네스 — 말로 하지 말고 재기

`bench/` 에 검사대를 뒀다. 고칠 때마다 돌린다.

```bash
npm run bench      # 규칙 + 규약 + 중계 서버. 키가 필요 없다
npm run bench:ai   # AI 일관성·멱등성. GEMINI_API_KEY 가 있어야 한다
```

**골든 세트**(`bench/cases.mjs`)는 글마다 두 가지를 적어 둔다.

- `expect` — 이 글에서 **반드시 잡아야 하는** 조각
- `keep` — **절대 건드리면 안 되는** 조각 (등산로·진로·평가·높이기(UP) 같은 것)

`keep` 이 있는 것이 핵심이다. 규칙을 넓히다 멀쩡한 말을 건드리는 사고를 이 도구에서 여러 번
냈다(발열→발렬, 진로→진으로). 잡는 것만 재면 그 사고가 안 보인다.

만들자마자 하나 잡혔다. `락밴드 → 록 밴드` 는 규칙이 못 보고 **2차 AI 검토에서만** 나오던
것이었다. 표기 사전에 넣었고 이제 규칙이 잡는다.

`bench:ai` 가 재는 것.

| | |
|---|---|
| ① 일관성 | 같은 글을 N 번 돌려 지적 묶음이 얼마나 겹치나(자카드), 수정본이 몇 가지 나오나 |
| ② 멱등성 | 수정본을 **다시 넣었을 때** 또 고치라는 것이 몇 개인가 |
| ③ 되돌림 | 그중 앞서 제대로 고쳐 놓은 것을 되돌리려는 것이 있나 |

③ 이 0 이 아니면 지시문의 울타리가 뚫린 것이다. 이 도구가 실제로 `높이기(UP)` 를 `높이기` 로
되돌린 적이 있어서 만든 항목이다.

`bench/worker.test.mjs` 는 중계 서버의 문을 확인한다 — 허용된 주소·모형만 지나가고, 남의
사이트·Origin 없는 요청·긴 원고·GET 이 막히고, 응답에 키가 섞여 나가지 않는지.

## 같은 글이면 같은 답이 나오게

세 단계 모두 **`temperature: 0`** 으로 부른다. 안 정해 두면 회사 기본값(대개 1.0)이라 같은
글을 두 번 넣어도 답이 달라진다. 온도를 못 박는 것이 결과를 일정하게 만드는 가장 싼 방법이고,
전에는 이걸 안 하고 있었다.

온도 0 이 완전한 결정성을 주지는 않는다(회사 쪽 배치 처리 때문에 흔들림이 남는다). 그래서
3단계 검수를 같이 둔다. 흔들려서 나쁜 답이 나와도 넣기 전에 한 번 더 걸린다.

## 두 번 돌리면 다른 답이 나온다

같은 글을 AI 검토에 두 번 넣으면 두 번째에도 고칠 것이 나온다. 실제 보도자료 한 건으로
확인해 보니 2차가 네 곳을 바꿨는데 **셋은 맞고 하나는 해로웠다.**

| 2차가 바꾼 것 | 판정 |
|---|---|
| 락밴드 → 록 밴드 | 맞다. 외래어 표기법대로다 |
| 운영한다 → 운영했다 | 맞다. 글 전체가 과거형인데 그 문장만 현재형이었다 |
| 마련 했다 → 마련했다 | 맞다. ‘마련하다’ 는 한 낱말이다 |
| 높이기(UP) → 높이기 | **해롭다.** 1차가 제대로 붙인 병기를 2차가 떼어 냈다 |

앞의 셋은 1차가 놓친 것이다. **한 번 돌려서 다 잡히지 않는다**는 뜻이고, 이건 모형이 매번
다르게 답하기 때문이라 없앨 수 없다. 두 번 돌리는 것이 낫다.

문제는 넷째다. 스스로 고쳐 놓은 것을 스스로 되돌렸다. 그래서 지시문에 울타리를 쳤다.

- 한글 뒤 괄호에 로마자를 넣은 것(‘높이기(UP)’)은 **이미 바른 표기이니 괄호를 지우지 마라**
- 작은따옴표나 「 」 안의 표어·행사명은 **그 기관이 정한 이름이니 다시 쓰라고 하지 마라**
- 시제는 한 문장만 보지 말고 **글 전체에 맞춰라**

넷째 같은 것을 규칙으로 막을 수는 없다. 되돌리지 말라고 이르는 것이 할 수 있는 전부다.
그래서 **수정본은 사람이 한 번 읽어야 한다.** 켜고 끄는 체크상자를 둔 이유가 이것이다.

## 규칙이 못 하는 일 — 구조적으로

조사·호응·비문은 규칙으로 안 된다. 규칙을 덜 만들어서가 아니다.

`공연로` 는 조사가 틀린 것이고 `진로`·`등산로` 는 멀쩡한 낱말이다. 이걸 가르려면 **그것이
낱말인지 아닌지** 를 알아야 하고, 그건 사전과 형태소 분석기가 하는 일이다. 문자열을 짜맞춰서는
못 한다.

형태소 분석기(Kiwi)를 실제로 붙여서 확인했다.

```
공연로  → 공연/NNG + 로/XSM     (갈라진다 = 조사)
진로    → 진로/NNG              (한 낱말)
등산로  → 등산로/NNG            (한 낱말)
등를    → 등/NNB + 를/JKO       (조사, 받침이 안 맞는다)
```

완벽하게 갈라 준다. **그런데 모델이 104MB 다.** 파일을 하나씩 빼 보았지만 전부 필요했다.
정적 웹페이지에 실을 수 있는 크기가 아니다.

그래서 이 도구에서 조사·호응·비문은 **AI 몫이다.** 규칙을 더 넣어서 좁힐 수 있는 간극이
아니라 구조가 정한 선이다. 화면도 그렇게 말한다 — ‘AI까지 검토’ 가 기본 단추이고,
‘규칙으로만 검토’ 는 아직 키를 넣지 않았을 때 쓰는 **반쪽 검사**라고 적어 두었다. 규칙만 돌리면
결과 위에 무엇을 안 봤는지 띄운다.

## 조사 받침 — 넣은 것과 안 넣은 것

`등를 → 등을` 은 규칙이 잡는다. `공연로 → 공연으로` 는 안 잡는다. 같은 조사 문제인데 갈린다.

| | 우리말에 그런 낱말이 | 판정 |
|---|---|---|
| 받침(ㄹ 제외) + `를` | 없다 | **규칙으로 잡는다** |
| 받침 없음 + `으로` | 없다 | **규칙으로 잡는다** |
| 받침(ㄹ 제외) + `로` | 진로·경로·근로·등산로·산책로·순환로… | 안 잡는다 |
| 받침 + `가` | 평가·물가·국가·불가… | 안 잡는다 |
| 받침 없음 + `이` | 아이·나이·사이… | 안 잡는다 |
| 받침 + `는` | 먹는·없는·읽는·받는… | 안 잡는다 |
| 받침 없음 + `과` | 교과·효과·초과… | 안 잡는다 |

세어 본 값이다. 가진 자료(첨삭 사례 419건 + 용어 1,540개)에서 `받침+를` 은 **오탐 0개**,
나머지는 갈래마다 6~16개가 걸렸다. 김제 보도자료 한 장만 넣어도 `받침+로` 규칙은 **‘진로’ 를
네 번 잘못 잡는다.**

ㄹ 받침은 `를` 쪽에서도 뺀다. ‘잠깐 들를 예정’ 의 `들를` 이 진짜 말이다.

AI 도 이런 것을 잡기는 한다. 다만 부를 때마다 답이 달라져서 **`등를` 을 놓친 적이 있다.**
규칙은 매번 같은 답을 낸다. 기계가 확실히 아는 것은 규칙이 맡고, 나머지를 AI 에게 넘긴다.

## 받침을 보는 또 한 곳

‘공연로 → 공연으로’ 같은 것은 규칙으로 될 것처럼 보인다. 받침만 보면 되니까. 그런데 `로` 로
끝나는 낱말이 전부 조사인 것이 아니다. 가지고 있는 자료(첨삭 사례 419건 + 용어 1,540개)만
훑어도 **벽난로·안전로·탐방로**가 걸리고, 실제 보도자료에는 등산로·산책로·순환로·진입로·
대피로가 흔하다. 2글자 이하를 빼도 경로·진로·근로가 남는다.

받침을 보는 것은 **우리가 갈아 끼우는 자리**에서만 안전하다. 그 자리는 앞말이 무엇인지 확실히
알기 때문이다(`agreeJosa`). 남의 글에서 조사를 찾아내는 일은 규칙이 할 수 있는 일이 아니다.
`발열 → 발렬`(두음 법칙을 열/렬까지 넓혔다가 생긴 사고)과 같은 종류의 실수다.

## 자동 수정

답이 하나로 정해지는 지적은 **자동으로 고쳐진 수정본**이 바로 나오고, 고친 자리는 초록으로
칠해집니다. ‘원래 말 같이 보기’를 켜면 고치기 전 말이 취소선으로 함께 보입니다.
`모두 고치기` / `모두 되돌리기` 로 한꺼번에 켜고 끌 수 있고, 항목마다 따로 켤 수도 있습니다.

기계가 답을 정할 수 없는 자리는 두 가지로 메웁니다.

1. **로마자 병기 사전**(`ROMAN_KOREAN`) — `AI → 인공지능(AI)` 처럼 병기 형태가 정해진
   약어 50여 개는 자동으로 고칩니다.
2. **AI로 채우기** — `~을 통해` 처럼 앞말에 따라 달라지는 것은 문장을 같이 보내 그 자리에
   그대로 끼울 말을 받아 옵니다(`fillBlanks()`). ‘AI까지 검토’ 를 고르면 검토와 함께 자동으로
   돌고, 규칙만으로 검토했더라도 `못 고친 n곳 AI로 채우기` 로 뒤늦게 채울 수 있습니다.
   자리표시(`~`, `(으)로`)가 섞여 오면 버립니다.

그래도 남는 것은 지적 카드의 **직접 적어 넣는 칸**에 쓰면 수정본에 들어갑니다.

넣을 때 두 가지를 기계가 검사합니다.

- **조사 맞추기**(`agreeJosa`) — 갈아 끼울 말이 조사로 시작하면 앞말 받침에 맞춥니다.
  ‘실습 등을 통해’ 의 ‘을 통해’ 를 AI가 ‘를 접하며’ 로 주면 ‘등를’ 이 되므로 ‘을 접하며’ 로 바로잡습니다.
- **시제 지키기**(`tenseChanged`) — ‘시간을 갖게 되었다 → 시간을 갖는다’ 처럼 시제가 바뀐 제안은
  넣어 두되 **체크를 꺼 둡니다.** 보도자료는 이미 있었던 일을 적는 글이라 시제가 틀어지면 안 됩니다.
예시 초안 기준으로 29건 중 자동 수정 17곳, 남는 것은 1곳입니다.

## 한글 파일 읽고 쓰기

브라우저 안에서 직접 처리합니다. 서버도 변환기도 쓰지 않습니다.

- `src/lib/hwp.ts` — .hwp(OLE 복합문서 + zlib)와 .hwpx(ZIP + XML)를 읽는다.
  `jbe-press-release-assistant/scripts/hwp_text.py` 를 타입스크립트로 옮긴 것이고,
  제목·부제·배포일·보도시점·사진/영상·배포 부서·담당자까지 뽑아 낸다.
- `src/lib/hwpxOut.ts` — 전북교육청 양식 hwpx의 자리표시를 갈아 끼워 새 파일을 만든다.
  `scripts/make_hwpx.py` 와 같은 방식이라 서식(글꼴·표·여백)은 그대로 남는다.
- `src/data/template.ts` — 양식 hwpx를 base64로 묻어 둔 것.
  원본은 `jbe-press-release-assistant/templates/jbe-press-release-form.hwpx`.
  **양식이 바뀌면 이 파일을 다시 만들어야 한다.**

  ```bash
  python3 - <<'EOF'
  import base64
  b = open('../jbe-press-release-assistant/templates/jbe-press-release-form.hwpx','rb').read()
  s = base64.b64encode(b).decode()
  lines = [s[i:i+120] for i in range(0, len(s), 120)]
  out = "export const TEMPLATE_HWPX_B64 =\n"
  out += "\n".join("  '%s' +" % l for l in lines[:-1]) + "\n  '%s';\n" % lines[-1]
  open('src/data/template.ts','w').write(out)
  EOF
  ```

## 원고는 어디로 가나

- 규칙 검사: 브라우저 안에서만 처리합니다. 서버로 아무것도 보내지 않습니다.
- AI 검토: 사용자가 설정에서 키를 넣고 버튼을 눌렀을 때만, 그 회사의 API로 전송됩니다.
  가는 것은 **제목·부제·본문뿐**입니다(`composeSource()`). 배포일·부서와 **과장·담당·담당자의
  이름과 전화번호는 가지 않습니다** — 머리말은 검사 대상이 아니라 브라우저 안에만 있다가
  hwpx 를 만들 때 쓰입니다. 키도 브라우저 저장소에만 남습니다.

## 배포

`.github/workflows/pages.yml` 이 `main` 에 push 될 때마다 빌드해서 GitHub Pages 에 올립니다.
처음 한 번만 아래를 하면 됩니다.

```bash
git remote add origin https://github.com/<계정>/jbe-press-release-checker.git
git branch -M main
git push -u origin main
```

그다음 저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 바꿉니다.
(기본값인 'Deploy from a branch' 로 두면 워크플로가 올린 결과가 나오지 않습니다.)

배포된 주소는 `https://<계정>.github.io/jbe-press-release-checker/` 입니다.
이후로는 고친 것을 push 하기만 하면 2~3분 안에 반영됩니다.

원고는 배포된 뒤에도 브라우저 안에서만 처리됩니다. 서버가 없으니 올라갈 곳도 없습니다.
